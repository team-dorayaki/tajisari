# AI 분석 v3.1 low / medium / dual35 / dual36 비교

실행일: 2026-09-09  
공통 입력: `ai/test3_1.png`, `ai/test3_2.png`, `ai/test3_3.png`  
출력 스키마와 후처리: AI 분석 JSON v3.1

## 구성

| 방식 | 고정 필드 | 가변 비용 | thinking |
|---|---|---|---|
| v3.1 low | 3.5 Flash Lite 단일 분석 | 동일 호출 | low |
| v3.1 medium | 3.5 Flash Lite 단일 분석 | 동일 호출 | medium |
| dual35 | 3.5 Flash Lite | 3.5 Flash | low / low |
| dual36 | 3.5 Flash Lite | 3.6 Flash | low / low |

dual35와 dual36은 두 모델을 병렬 호출하고 Python 서버에서 결과를 병합한 뒤 기존 v3.1 후처리를 한 번 적용한다. 서버에서는 `AI_ANALYSIS_MODE=dual35` 또는 `dual36`으로 선택한다. 기본값은 dual36이다.

## 결론

이번 test3 표본에서는 **v3.1 medium의 판정 정확도가 가장 높았고, v3.1 low가 가장 빠르고 토큰 사용량이 적었다.**

3.6 Flash로 바꾼 dual36은 정답 비용 11개를 모두 추출했지만 dual35보다 개선되지 않았다. 오히려 비용이 아닌 `중개수수료 제로/불필요`와 `보증금 차감 불필요`를 가변 비용 행으로 저장해 오탐이 2건 발생했다. 가변 비용용 3.6 Flash 응답이 67.24초 걸려 전체 시간도 dual35보다 길었다.

다만 API 가격은 3.6 Flash가 3.5 Flash보다 낮다. 동일 계열 호출의 실제 토큰을 현재 표준 가격에 적용하면 가변 비용 호출 추정 비용은 dual35 약 $0.056, dual36 약 $0.025다. 토큰 외 고정 비용과 무료 등급은 제외한 근사치다.

## 시간과 API 사용량

각 결과는 동일한 이미지 3장을 사용한 1회 실행이다. dual35는 3.6 변경 직전 측정값, dual36은 변경 직후 측정값이다.

| 방식 | API 호출 | 전체 시간 | 입력 토큰 | 출력 토큰 | thinking 토큰 | 총 토큰 |
|---|---:|---:|---:|---:|---:|---:|
| v3.1 low | 1 | 18.52초 | 5,399 | 5,459 | 0 | 10,858 |
| v3.1 medium | 1 | 28.70초 | 5,399 | 6,677 | 2,996 | 15,072 |
| dual35 | 2 | 43.72초 | 11,052 | 8,337 | 0 | 19,389 |
| dual36 | 2 | 67.27초 | 11,052 | 8,854 | 0 | 19,906 |

| dual 내부 호출 | API 응답 | 입력 | 출력 | thinking | 총 토큰 | 캐시 |
|---|---:|---:|---:|---:|---:|---:|
| dual35 / 3.5 Flash Lite 고정 | 11.94초 | 5,510 | 2,663 | 0 | 8,173 | 0 |
| dual35 / 3.5 Flash 비용 | 43.69초 | 5,542 | 5,674 | 0 | 11,216 | 2,845 |
| dual36 / 3.5 Flash Lite 고정 | 12.41초 | 5,510 | 3,169 | 0 | 8,679 | 0 |
| dual36 / 3.6 Flash 비용 | 67.24초 | 5,542 | 5,685 | 0 | 11,227 | 0 |

dual36은 dual35보다 전체 시간이 53.9% 증가했고 총 토큰은 2.7% 증가했다. 두 dual 모두 비용 모델 호출이 전체 시간의 병목이었다. API 응답 시간은 변동성이 크므로 한 번의 실행으로 3.6이 항상 느리다고 단정할 수는 없다.

## 정확도 기준

이미지에서 확인되는 가변 비용 정답은 다음 11개다.

1. 월정액 주차장 `¥4,400~`
2. 화재보험 `2년 ¥13,130~¥26,680`
3. 갱신료 `¥16,500`
4. 환경유지비 `¥550/월`
5. 열쇠교환비/Smartlock 수수료 `¥16,500`
6. 퇴거 시 청소비 `¥52,250`
7. 항균시공 `(임의) ¥18,040~¥23,760`
8. 입주자 지원 시스템 플러스 `(임의) ¥18,975`
9. 보증 위탁료 `이용료의 100%~120%(계약 시)`
10. 보증 위탁료 `10,000엔(2년차 이후, 매년)`
11. 인터넷 이용료 `월 ¥3,630`

금액 범위·비율인 주차장, 화재보험, 항균시공, 초기 보증료는 `amount=null`을 정답으로 보았다. 명시적 `(임의)` 두 건만 OPTIONAL이고 나머지는 직접적인 의무 근거가 없어 UNKNOWN으로 평가했다.

timing 정답은 주차장·환경유지비·인터넷 `MONTHLY`, 갱신료·연간 보증료 `RENEWAL`, 퇴거 청소비 `MOVE_OUT`, 계약 시 보증료 `INITIAL`이다. 열쇠교환비, 화재보험, 항균시공, 입주자 지원은 납부 시점이 직접 표시되지 않아 `UNKNOWN`이 더 보수적이다.

| 최종 비용 행 / 후보 | 11 / 11 | 11 / 11 | 12 / 17 | 13 / 17 |

### dual35 결과

- 정답 비용 11개를 모두 추출했다.
- 항균시공과 입주자 지원을 OPTIONAL로 판정했다.
- 주차장의 `이용 가능`을 선택 근거로 해석해 OPTIONAL로 추정했다. v3.1 규칙상 UNKNOWN이 더 보수적이다.
- `보증금 차감 불필요`를 비용으로 추가해 오탐 1건이 발생했다.
- 화재보험과 시점 미기재 비용들에 근거 없는 INITIAL을 부여했다.

### dual36 결과

- 정답 비용 11개와 계약 시/매년 보증료 분리를 모두 유지했다.
- 항균시공과 입주자 지원을 OPTIONAL로 판정했다.
- dual35와 마찬가지로 주차장을 OPTIONAL로 추정했다.
- `중개수수료 제로/불필요`, `보증금 차감 불필요`를 별도 비용으로 저장해 오탐 2건이 발생했다.
- 화재보험의 `2년`은 계약 기간인데 timing을 INITIAL로 판정했다.
- 열쇠교환비, 항균시공, 입주자 지원에도 직접 근거가 없는 INITIAL을 부여했다.

## 선택 판단

| 목적 | 현재 결과상 선택 |
|---|---|
| 최소 응답 시간·토큰 | v3.1 low |
| test3 판정 정확도 | v3.1 medium |
| 더 저렴한 dual 비용 모델 | dual36 |
| 두 dual 중 이번 표본 정확도 | dual35 |

3.6 Flash는 호출 단가는 낮지만 이번 한 번의 결과에서는 품질과 응답 시간이 개선되지 않았다. dual36을 운영 기본값으로 쓰기 전에는 `불필요/제로` 문구를 가변 비용에서 제외하는 후처리와 명시적 시점이 없는 항목을 UNKNOWN으로 강제하는 검증을 추가하는 편이 안전하다.

## 검증 정보

- 프리셋: `single`, `dual35`, `dual36`
- 두 dual 프리셋 모두 `thinking_level="low"`
- 테스트: `26 passed`, 의존성 deprecation warning 2개
- 테스트 이미지는 Git에 포함하지 않음
- dual35 원시 결과: `ai/benchmark-results/three-way-test3/`
- dual36 원시 결과: `ai/benchmark-results/three-way-test3-dual36/`
- 비교 실행기는 이후 실행부터 low, medium, dual35, dual36 네 방식을 모두 실행한다.

모델 출력은 확률적이고 각 방식 1회 측정이므로 운영 결정을 위해서는 실행 순서를 섞어 최소 3회 이상 반복하는 것이 적절하다.

브랜치 `feat/ai-rule-based-cost-validation`에서 dual36 모델 구성은 유지하고 Python 후처리를 강화한 뒤 같은 test3 이미지 3장을 다시 분석했다.

규칙 적용 후 `중개수수료 제로/불필요`와 `보증금 차감 불필요`가 가변 비용에서 제거됐다. 주차장은 UNKNOWN, 명시적 `(임의)`가 있는 항균시공과 입주자 지원만 OPTIONAL로 확정됐다.

timing은 다음과 같이 교정됐다.

- 주차장·환경유지비·인터넷: `MONTHLY`
- 갱신료·연간 보증료: `RENEWAL`
- 퇴거 청소비: `MOVE_OUT`
- 계약 시 보증료: `INITIAL`
- 화재보험·열쇠교환비·항균시공·입주자 지원: `UNKNOWN`

금액 범위와 비율은 모두 `amount=null`로 유지했고 직접 표시된 단일 금액은 엔화 정수로 보존했다. 실측 호출은 3.5 Flash Lite 고정 필드 15.05초, 3.6 Flash 가변 비용 33.79초였으며 두 요청은 병렬 실행됐다. 테스트는 `38 passed`다. 이 결과도 1회 측정이므로 응답 시간 개선을 규칙 변경의 효과로 단정할 수는 없지만, 최종 JSON의 판정 결과는 정의한 test3 정답을 모두 충족했다.
